# Publish NanoVLM on GitHub and Hugging Face

These files are an **overlay** for your existing WSL project. Extract them into `~/projects/NanoVLM/` without replacing your **locally trained notebook**, `nanoflash_cuda.py`, `test_nanoflash.py`, or `nanovlm-medic-adapter/`.

## A. Verify your local assets

```bash
cd ~/projects/NanoVLM
source .venv/bin/activate
ls -l nanoflash_cuda.py test_nanoflash.py
find nanovlm-medic-adapter -maxdepth 1 -type f -printf '%f\n'
python test_nanoflash.py
```

Your model directory should contain at least `adapter_config.json`, adapter weights (e.g. `adapter_model.safetensors`) and processor/tokenizer configuration. The ZIP release kit intentionally **does not include** your trained weights because they exist only on your laptop.

## B. Clean the public notebook

Jupyter outputs may contain large embedded images, logs, private paths, or credentials. Review notebook cells for secrets and licensed medical images before publishing.

```bash
python scripts/clean_notebook.py *.ipynb
# Only if review looks good (backups are created):
python scripts/clean_notebook.py --write *.ipynb
```

This clears outputs, **not** model weights, and leaves a `.ipynb.bak` local backup. The training plots are included separately as `assets/training_curves.png`.

For an exact software environment snapshot:

```bash
python -m pip freeze > environment_lock.txt
```

Review package indices, URLs and any private strings in the lock file before adding to Git.

## C. Publish source to GitHub

Create an **empty public repository** named `NanoVLM-CUDA-FlashAttention` on GitHub (no autogenerated README / .gitignore). Then:

```bash
cd ~/projects/NanoVLM
git init
git branch -M main
# Replace YOUR_GITHUB_USERNAME:
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/NanoVLM-CUDA-FlashAttention.git

git add README.md .gitignore requirements.txt HF_MODEL_CARD.md PUBLISHING.md scripts/ assets/
git add nanoflash_cuda.py test_nanoflash.py
git add *.ipynb
# Optional: git add environment_lock.txt
git status --short
git diff --cached --stat
git commit -m "Release NanoVLM custom CUDA FlashAttention research prototype"
git push -u origin main
```

If `origin` already exists, check `git remote -v` and use `git remote set-url origin URL`. Authenticate using GitHub CLI (`gh auth login`) or an SSH key/credential manager; **don't paste a GitHub token directly in repository files**. Do not commit `nanovlm-medical-checkpoints`, the `.venv` folder, model weights, or SLAKE image archives.

## D. Publish trained adapter to Hugging Face

```bash
python -m pip install -U huggingface_hub
hf auth login
hf auth whoami
python scripts/publish_hf.py --repo-id YOUR_HF_USERNAME/nanovlm-slake-500m-qlora
# After verifying the preview, actually upload:
python scripts/publish_hf.py --repo-id YOUR_HF_USERNAME/nanovlm-slake-500m-qlora --yes
```

`--private` creates a new private repo if it doesn't already exist; it doesn't change visibility of an existing repository. The Python script only uploads the files from your adapter directory plus the model card. If you want a pure CLI alternative, copy `HF_MODEL_CARD.md` to `nanovlm-medic-adapter/README.md` then run:

```bash
hf upload YOUR_HF_USERNAME/nanovlm-slake-500m-qlora nanovlm-medic-adapter .
```

## E. Check that it works **from a fresh environment**

- Clone the new GitHub repo on your WSL computer or a second machine.
- Install CUDA-compatible PyTorch and `requirements.txt`.
- Run `python test_nanoflash.py`.
- Load the original SmolVLM base model using `attn_implementation=register_nanoflash()` **before** loading the adapter with `PeftModel.from_pretrained(base, 'HF_USERNAME/REPO')`.
- Load processor from the HF model repository and reproduce a few held-out predictions using the notebook prompt code.
- Compare reproducibility with your original 74.55% EM / 78.64% F1 test results; do not claim this is a new independent test without running it.

## F. Finish the release

Update the links in `README.md` and `HF_MODEL_CARD.md`. Clearly label the artifact as a research-only medical VQA system. Verify upstream model/dataset terms before licensing the repository or redistributing images.
